PADOS 的核心能力

核心是讓 PADOS 掌握任務與結果的治理鏈；模型與 domain pack 是可替換擴充。

1 · 意圖與任務完整性

保留原始意圖、project、scope、classification 與 goal lineage；拒絕 provider 重寫任務身份。

2 · 治理與授權

檢查 policy、grant、scope、分類、approval 與 runtime identity，再允許派工。

3 · 能力與資源協調

透過唯一 scheduler、既有 router、registry 和 resource inventory，選擇合適 worker / provider。

4 · 受控執行與可攜性

用 bounded adapter、sandbox、compute node 和 execution contract，跨本機、遠端工具與模型執行。

5 · 證據與驗證

保存 receipts、artifact digests、provenance 與 runtime evidence；檢查 coverage、輸出契約和結果來源。

6 · 治理接受與持久化

ResultCandidate 經驗證與 approval，再走既有 CAS / audit；execution success 不等於 acceptance。

7 · 上下文與受控學習

Memory、retrieval、discovery 和 outcome learning 提供資料或建議，不取得派工、授權或 promotion 權限。

不是 PADOS Core 本身的能力：OCR、8D、AI Scientist、REA、OpenMAIC、MCP tool 與特定模型是擴充能力/provider。它們可以增加可處理的任務種類，但不能擁有 Task、policy、scheduler、router、verification 或 CAS。

資料、Authority 與安全邊界

「誰能決定」和「資料存在哪裡」分開表達。

Intent / Task

Authenticated intake 將原始 intent 捕捉為 TaskEnvelope；project、classification、ScopeVersion 與其它任務欄位由 PADOS 綁定。

PADOS authority

Queue / selection

Existing scheduler 是唯一 queue order；既有 router/planner 在 policy、grant 和 resource constraints 下選可行能力。

one scheduler + router

Execution evidence

Provider output 不可信；PADOS 綁定 identity、authorization、provenance、artifact digest、receipt 和 runtime/device/config evidence。

evidence ≠ truth

Verification / acceptance

Coverage、composition 與 verifier 形成 ResultCandidate；再走 governed decision 和既有 CAS semantic commit。

single CAS path

Truth sources（CONSTITUTION）

Operational state：PostgreSQL。Semantic knowledge：version-controlled Markdown Wiki。Artifact truth：immutable SHA-256 references。各 receipt/audit log 的實際 storage 依 implementation。

truth source separation

Projection

Work Graph、Remote views、Work Map 是 rebuildable/read projections。不得把 projection 當 semantic write authority。

projection only

元件能提供不具備的 authority原始碼位置

部署拓樸與外部 Runtime

Adapter 的存在不等於 provider/runtime 已完成 live validation。

Home Base / local platform

  • Python 3.12+ modular monolith: FastAPI, CLI, domain/service packages.
  • PostgreSQL + Alembic; configured lanes/object roots depend on environment settings.
  • React 19 / TypeScript / Vite static Work Map, connecting to authenticated Home Base.
  • Local compute nodes provide registered runtime backends over node protocol.
  • Windows-native and VMware/Linux evidence must record actual OS/host/commit separately.

Replaceable providers / runtimes

  • Ollama via measured execution binding.
  • REA via optional stdio MCP capability discovery.
  • OpenMAIC via optional HTTP adaptive-learning adapter.
  • Codex / Claude adapters, OCR/PDF engines, MCP tools, deterministic algorithm resources.
  • All outputs return through PADOS receipts, verification, approval and existing semantic path.

Documented deployment profiles

LOCAL_SINGLE_USER / TRUSTED_LAN are documented profiles. HARDENED_ENTERPRISE is marked not supported yet; do not present it as shipped.

CI / static deployment

GitHub Actions provide build/test/security/supply-chain evidence. Pages serves static UI only. CI success does not authorize runtime deployment or semantic commits.

Live-validation status: README/PLANS explicitly mark real REA and OpenMAIC runtime validation as NOT_VALIDATED. AI Scientist real runtime is also not validated. Docker Compose describes an optional local database service; Windows Docker Desktop status is separate from VMware Linux validation.

已逐項對照目前 HEAD 的程式碼、文件及 gate evidence；可由 repo 解答的已釐清，外部驗證/產品風險/法律條件保留為明確 blocker。

開啟逐項證據、結論與 closure conditions

1. [已釐清：兩條工作流] Product Loop vs TaskLoop / WorkProtocol

同時存在 product_loop、loop、project_goal、work_protocol。確認產品入口與各自 lifecycle 的分工是否說明完整。

2. [程式碼已區分] Graph vs Work Graph

pados.graph 是 cognitive/context graph API；work_protocol.graph 是 task/receipt/acceptance lineage projection。確認 UI 與命名能避免混淆。

3. [共用 CAS 已核對] CAS path 與既存 product state wiring

確認各產品 workflow 的 ResultCandidate/acceptance 都收斂至既有 semantic CAS，並且 docs、route wiring、tests 證據一致。

4. [V1 殘留／需風險接受] Pack V1 enforcement limits

確認宣告式 timeout/egress/roots 等限制在 V1 的接受範圍；如需真正隔離執行，要另訂 runtime contract。

5. [NOT_VALIDATED] REA / OpenMAIC live runtime

Adapters 有 contract/failure tests；live runtime 仍 NOT_VALIDATED。確認 UAT evidence 與 owner。

6. [VMware 已核對／Windows 未關閉] Platform evidence

每個 gate 記錄 exact commit、OS、host、command、exit code 和 log path；VM evidence 不能由 Windows/WSL 猜出。

7. [V1 明確排除] Work Map Pack management

Pack V1 spec 將 UI 列為 non-goal。若期望安裝/註冊/授權/lifecycle UI，需另列需求；註冊不等於授權。

8. [Owner／legal gate 未關] Dependency provenance / licensing

此頁列 lockfiles，不等於 redistribution rights review。維持 third-party notices / provenance / license gate。

9. [有 boundary tests] Capability / Resource boundary

確認模型、OCR、algorithm、MCP/Agent、compute node 都只是 replaceable resources，policy/verification/acceptance 由 PADOS 持有。

10. [邏輯圖已釐清／實例待證] Database / object-store map

Repo 支援多 lane / object roots；要畫出某環境實際 DB、schema、volume，需 redacted config + migration evidence，不能由一般 repo topology 推測。

P0 production-readiness risks

  1. OP-001 · correlation/error chain: API → loop → capability/provider → evidence 尚未有一致可查詢的 request/correlation/run/project context 與 stable error envelope。
  2. OP-002 · runtime validation: PR #16/PR #17 的 named external runtimes 明確仍是 NOT_VALIDATED；不能把 adapter contract test 當成 live production evidence。

P1 risks

  1. Health / readiness / degraded semantics across /health, /ready, system_health 不完全收斂。
  2. Retry / timeout / idempotency / lease budgets 尚未跨 provider、worker、DB、browser 傳遞。
  3. CI 能證明 code quality 與 deterministic tests，但還不能強制 service contract、failure injection、recovery 與 live-lane status。
  4. Provider timeout、stuck job、expired lease、partial evidence、stale session 的 recovery path 分散在各文件。

Remediation roadmap

PHASE 0 · P0

凍結 versioned error envelope、context fields、PASS / FAIL / SKIPPED / NOT_VALIDATED vocabulary；加 read-only evidence index；缺 live evidence 時禁止 production wording。

PHASE 1 · P1

加 request context middleware、parent deadline/retry budget、health schema convergence、failure-injection/recovery tests、runbooks、CI operability gate、browser abort deadline。

PHASE 2 · P2

採用 bounded metrics 與 optional trace adapter，建立 queue/retry/lease/readiness dashboards；pack manifest 宣告 resource/runtime metadata。

PHASE 3 · P3

統一 glossary、event/error naming、runbook links 與 documentation lint。

Service standard checklist

  • Purpose、I/O、state、dependencies、API、events、resources、security 已記錄。
  • request/correlation/run/project IDs 可跨 API、queue、worker、provider、receipt、browser 追蹤。
  • logs 對 outcome、refusal、retry、timeout、lease loss、recovery 結構化且 redacted。
  • errors 有 stable code、category、retryability、safe message、write/evidence semantics。
  • deadline、retry、idempotency、lease/heartbeat 與 health semantics 已測試。
  • failure injection、recovery test、runbook 與 CI gate 能分辨 PASS / FAIL / SKIPPED / NOT_VALIDATED。
